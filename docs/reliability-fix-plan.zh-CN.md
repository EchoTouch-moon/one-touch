# 近期审查问题修改方案

> 2026-10-05：相关修改已落地，实际检查结果与未完成的环境验证见 [修复交付记录](fix-validation-2026-10-05.zh-CN.md)。以下保留原方案内容。

日期：2026-10-03。依据：a52cae6 及此前近期改动的本地审查。

## 目标与范围

修复六项已识别问题：容器缺词库、离线同步覆盖新增记录、账号缓存混用、离线时间丢失、词库分页计数错误、词典面板手势冲突。前三项优先。语料版本化列为后续增强，本轮不增加学习功能、不调整 SRS 算法、不操作线上服务。

审查基线：后端 33 项测试、前端构建、ESLint 通过；分页和离线队列问题已做最小复现。Docker 缺数据和账号隔离问题依据代码路径确认，尚未进行容器运行验证；手势问题需浏览器及触屏验证。

## 1. 补齐容器数据交付（独立提交）

文件：`Dockerfile.backend`、`backend/main.py`、`backend/services/kaoyan_service.py`、相关后端测试。

- 镜像显式复制 `data/kaoyan/kaoyan_words.json` 和 `exam_sentences.json` 到 `/app/data/kaoyan/`，避免顺带打包原始试卷等非运行必需文件。
- 启动导入前验证两个必需文件存在、可解析且结构有效；缺失时给出含具体路径的启动错误，避免静默提供空词库。保留原有数据库事务，验证失败不删除已有语料。
- 本轮沿用现有语料导入机制，版本化导入单独处理。

验收：新镜像配临时空数据库启动后，词数/句数与打包 JSON 一致，查询和收词成功；缺失文件时明确失败；已有临时数据库升级启动不影响用户词卡。只使用测试数据和临时容器卷。

## 2. 建立明确的账号边界（同步修复的前置提交）

文件：`backend/routers/auth.py`、`frontend/src/api/auth.ts`、`frontend/src/api/authSession.ts`、`frontend/src/store/authStore.ts`、`frontend/src/store/reviewStore.ts`、`frontend/src/utils/offlineReviewQueue.ts`、`frontend/src/App.tsx`。

- 登录和状态接口统一返回显式 `user_id`，前端持久化该字段。当前登录的 `username` 是邮箱，状态接口的同名字段却是 token 的 `sub`，不能直接用作缓存身份；同步统一其显示语义。
- 缓存键及队列存储带版本和用户 ID；读取、写入、同步接口显式接收所属用户，不在异步完成时重新猜测当前用户。
- 退出或切换账号时清空内存卡片、统计及当前会话状态；原账号已归属的待同步记录保留在其独立存储中，重新登录同账号后可继续。
- 复用已有会话 epoch，为加载、评分和同步捕获身份快照。每次发请求前核对身份，每次异步回写前核对 epoch；旧请求不能写入新用户的界面、缓存，也不能使用新用户凭据继续发送旧队列。
- 把模块级 `startSessionPromise` 改为会话范围内的任务，账号 B 不复用账号 A 的进行中任务。用户身份未确定时不预热复习缓存。
- 兼容旧登录状态：缺少 `user_id` 时先查询状态，确认身份后才读取新缓存。

旧数据处理：旧卡片缓存可丢弃并从服务器重建；旧待同步队列没有可信账号归属，不自动归给当前账号、不自动提交、不静默删除。保留隔离副本，有遗留记录时显示恢复提示并提供导出；不在本轮设计自动猜测归属的迁移。

验收：A 退出后 B 在线、慢网或请求失败时都看不到 A 的卡片；A 的延迟响应不影响 B；A 的队列不会以 B 的身份提交；A 重新登录仍能同步自己的记录；旧数据升级不误提交或删除待同步记录。

## 3. 修复离线队列和时间语义（在账号边界之后）

文件：`frontend/src/utils/offlineReviewQueue.ts`、`frontend/src/store/reviewStore.ts`、`frontend/src/api/review.ts`、对应前端测试；必要时补后端调度时间测试。

- 保留每条记录已有的唯一 ID；提交成功只删除对应 ID，不用启动同步时的旧快照覆盖整份队列。删除前读取当前队列，保留同步期间新增的数据。
- 同一账号、同一会话只运行一个同步任务；多个触发入口复用同一任务。发生临时网络失败时保留记录并停止本轮顺序提交，避免同一单词的后续评分越过失败记录。
- 保留并发送原始 `reviewed_at`；兼容旧记录缺失时间时使用其有效 `created_at`，两者均无有效时间则保留并提示，不伪造为当前时间。
- 有待同步记录时，新评分先进入同一有序队列，防止恢复联网后新评分先于旧评分直传。鉴权失败停止；永久性拒绝保留可见失败状态，不静默丢弃。
- 为 localStorage 读改写和同步增加跨标签页互斥（目标浏览器支持 Web Locks 时使用）。不支持该能力时明确限制并发同步；若必须完整支持这些浏览器的多标签页并发，改用 IndexedDB 事务，不能把单标签页 Promise 锁当作跨标签页保障。

验收：同步 A 期间新增 B，A 成功后 B 仍在；重复触发不会重复启动同一批次；失败记录保留；账号切换中止后续发送；隔天同步仍携带原始时间，后端日志和调度按该时间计算；按目标浏览器验证双标签页并发。

边界：上述方案不承诺网络请求的“恰好一次”语义。服务端已提交但响应丢失后重试，仍需服务端事件 ID 去重；多设备迟到评分也需要服务端冲突策略。这两项是离线可靠性的后续候选，应单独评估，不以客户端互斥已解决来表述。

## 4. 修正考研词库分页（独立提交）

文件：`backend/services/kaoyan_service.py`、`backend/tests/test_core_flows.py`、`frontend/src/pages/KaoyanLexiconPage.tsx`。

- 列表和 total 从同一组用户关联、搜索及状态条件生成；计数在分页之前执行。
- 前端收词成功后刷新当前筛选结果及总数，New 列表移除已收录词；最后一页失效时回到有效页。
- 给列表请求增加取消或序号保护，避免快速切换筛选时旧响应覆盖新结果。

验收：all/Mine/New、搜索与状态组合、无匹配、跨页、不同用户分别验证 total 与结果一致；在 New 最后一页收词不留下空页；慢请求乱序返回时保持最新筛选。

## 5. 分离查词与评分手势（独立提交）

文件：`frontend/src/components/FlashCard.tsx`、`frontend/src/pages/ReviewPage.tsx`，必要时涉及样式文件。

- 先复现长按松手、面板滚动和拖动评分冲突，再调整事件边界。
- 将词典模式提升到能控制拖动的组件层级；词典展开时禁用滑动评分，关闭后恢复。
- 长按触发后消费随后的首次 click；在取消、卸载、换卡时清理计时器及标记。
- 词典内容允许纵向滚动；同时调整外层 `touch-none`，只修改子层 `touch-action` 不足以恢复滚动。
- 保留明确的词典切换按钮。正常模式继续支持翻面、四方向评分、按钮和数字键。

验收：长按松手后面板保持打开；滚动长例句不评分；点击关闭后能正常翻面和滑动评分；短按、取消、快速换卡没有延迟弹出；桌面鼠标和至少一个目标触屏浏览器验证。浏览器模拟不能替代真机结果，无法取得设备时明确记录限制。

## 验证、提交顺序和完成标准

推荐提交顺序：1 → 2 → 3 → 4 → 5。部署与分页可独立验收，账号边界必须先于新的同步逻辑完成。

前端当前没有行为测试命令。补最小 Vitest 测试入口，用模拟存储、延迟 Promise 和可控时钟验证队列与状态；手势增加必要组件测试和浏览器场景，不扩展为全站测试改造。

每个提交运行相应定向测试；最终运行后端测试、前端构建和 lint，并完成临时容器检查及手势检查。通过后不无条件重复运行。修复完成需提供上述验收结果、旧缓存处理结果，以及未能验证的环境限制。

## 后续增强候选

- 语料版本或摘要驱动导入：减少每次启动重建真题表的写入；不属于本轮六项缺陷的必要条件。
- 服务端同步事件幂等、跨设备迟到事件策略：需要独立的数据与兼容性设计。
- 本轮不增加新的学习功能，也不改变卡片视觉风格。
