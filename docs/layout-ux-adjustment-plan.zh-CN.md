## 1. 全局布局：底部导航和页面共用一套空间规则

现状：手机顶部持续显示 Feedback、Log out，底部固定五项导航；页面通过 `pb-24` 自行避让。复习页另有接近整屏的最小高度，实际高度再加上主容器底部留白。固定备案页脚也可能与操作区竞争空间。桌面顶部使用 max-w-4xl，列表和详情使用 max-w-5xl，内容边界不一致。

方案：

- 保留现有五个主入口及顺序，避免本轮改变已形成的导航习惯。
- 手机顶部将 Feedback、Log out 收到有明确名称的账号菜单；反馈和退出仍可一步展开找到。桌面也使用同一账号菜单，减少顶部拥挤。
- 定义统一的顶部高度、底部导航高度、安全区和页面底部间距变量。底部导航包含 `env(safe-area-inset-bottom)`；内容区按实际导航占位，不在各页重复叠加整屏高度。
- 备案信息移到正常文档流的公共页脚，长页面到底可访问，不悬浮覆盖画布、按钮或卡片。
- 列表、词典和详情使用同一宽容器及左右边距；收词、复习保留更窄的专注容器。宽屏留白合理存在，不为填满屏幕加入额外面板。
- 当前 640px 就切换完整桌面导航；实施时重点检查 640–767px。以导航实际能否容纳为准调整断点，不能只按设备名称判断。

文件：`frontend/src/App.tsx`、`frontend/src/index.css`、`frontend/src/components/IcpRecordLink.tsx`。

## 2. 复习页：先保证评分，再分配卡片高度

已观察：375×667 的反面中，Again 按钮顶部约 643.7px，底部约 693.7px；底部导航从约 603px 开始。按钮被遮挡且超出视口，卡片却占用了主要空间。

方案：

- 结构改成三段：紧凑会话头部 → 可伸缩卡片区 → 始终可达的评分区。先预留评分区和导航高度，剩余空间再给卡片。
- 合并进度标题、剩余数量和进度条；View details 收入卡片附近的小入口，不单独占完整一行加大间距。
- 正面底部放明确的 Show answer 按钮，保留点击卡片和空格翻面；翻面后在同一区域显示 Again / Hard / Good / Easy 四个评分按钮。
- 普通字号、375×667 下四个评分按钮必须首屏完整显示，不能要求先滚动。极短横屏或大字号允许正常页面滚动，不能通过裁切内容或缩小到难读字号强行塞入。
- 卡片改为按可用高度约束；长释义在卡内可滚动，手写图保持比例，提供现有详情入口查看完整内容。卡片堆叠的装饰偏移不能挤出评分区。
- 查词采用独立模式：进入后暂停滑动评分，保留显式返回按钮。同步落实可靠性方案中的长按松手与滚动冲突修复。
- 统一滑动提示与评分按钮用词：当前同一评分在滑动提示为 Remember、按钮为 Good，应一致。手机优先展示按钮，手势作为可选快捷操作。
- 区分“没有任何词卡”“已有词卡但今日无到期任务”“请求失败”“离线缓存不可用”。今日已完成时显示完成状态及去词库入口，不再引导已有用户去创建第一张卡。

建议结构：

```text
简洁顶部 / 账号入口
返回    第 1/3 组 · 剩余 4 张
──────── 进度 ────────
┌────────────────────┐
│ 单词 / 释义 / 手写图  │  卡片区随可用高度伸缩
│              查词   │
└────────────────────┘
Again   Hard   Good   Easy   评分区完整可见
收词    复习    词库    考研    设置
系统安全区
```

文件：`ReviewPage.tsx`、`FlashCard.tsx`、`ReviewControls.tsx`、必要的 `reviewStore.ts` 状态区分。

## 3. 收词：把提交、保存和继续收词做清楚

已观察：入口仅有输入框，真实提交按钮是隐藏的；手机主要依赖占位提示和软键盘 Enter。标题与输入整体居中但周围留白较多，软键盘出现后的可用空间尚未真机验证。源码中 “in this session” 使用共享词库数组长度，访问词库后会混入列表数据。

方案：

- 桌面输入框右侧显示 Capture，手机在输入框下方显示全宽主按钮；Enter 保留，输入使用英文友好的自动大小写、拼写检查及提交键配置。
- 用短标签说明输入内容，placeholder 只放示例，避免长提示在手机输入框内被截断；输入错误放在字段下方。
- 提交时按钮显示进行中并防止重复操作。重复单词给出 Open existing card，而不是把“已存在”和“网络失败”合并为同一错误。
- 移动端把输入区放在上半屏，减少强制垂直居中；自动聚焦需验证软键盘影响，不能让底部导航遮住提交按钮。
- 保留已经记忆的手写/键盘偏好，模式切换放在编辑头部，避免重复选择。
- 手写保存会回到收词入口，文字保存会继续留在编辑页。明确文案区分 Save & next 与 Add meaning；保留继续补充释义的路径，避免相同 Save 文案产生不同结果。
- 保存成功显示“已保存，可复习”及查看词卡入口；失败保留输入和笔迹，并提供重试。这里只表达服务器已保存的事实，不把本地草稿称为已保存词卡。
- 本次收词数量使用独立会话状态；最近收词与当前分页词库分离。最近词条做成可点击详情入口，缺释义的词显示 Continue editing。

文件：`QuickCapturePage.tsx`、`wordStore.ts`、必要的收词错误类型和 API 返回处理。

## 4. 我的词库：搜索优先，删除退到次级操作

已观察：375px 宽度时搜索输入被按钮和页容量选择器挤窄；每个词条第一行是单词及两个状态标签，第二行主要是 delete。删除直接调用接口，没有确认；搜索无匹配也显示 No words yet。

方案：

- 手机搜索框独占一行；页容量移到分页底部。与考研词库统一为输入短暂防抖检索，Enter 可立即检索，提供清空入口。
- 一行主要表达单词、可复习状态和进入详情。合并重复状态，后台 captured/enriched 不与用户所需的“待补释义/可复习”争抢空间。
- 将删除收进行尾更多菜单或详情页，执行前显示明确的单词名及影响并确认。后端没有可撤销删除能力时，不显示虚假的 Undo。
- 在当前 API 支持范围内重排，不为每个词额外请求详情。如果需要列表释义摘要，作为独立增强扩展列表响应后再做，避免 N+1 请求。
- 搜索无匹配显示“No matches”和清空条件；真正空词库才引导 Capture；网络错误显示 Retry，保留上次内容但标记尚未刷新。
- 返回列表时恢复搜索词、页码和滚动位置；页容量变更保留搜索条件。手机分页用上一页、页数、下一页，避免大量页码挤出屏幕。

文件：`WordListPage.tsx`、`wordStore.ts`、详情页返回处理。

## 5. 考研词库：优先展示释义与收录状态

已观察：手机每行的单词占固定宽度，释义只能展示很短一段；`frq 137` 等数字仍占右侧空间。收词按钮藏在展开内容和例句之后，用户需展开再寻找。搜索、筛选及标题存在中英文混用。

方案：

- 手机使用两行词条：第一行单词、收录状态/动作，第二行中文释义摘要。桌面继续紧凑列表，可保留音标列。
- 移除行内裸露 frq 数字，放到展开详情并解释为通用词频排名；不能把该字段包装成“考研出现频次”。
- 将 Capture with definition 的操作放在行尾或展开区顶部，释义和真题放在其后。按钮与展开行使用独立交互区域，避免嵌套按钮或点击收词同时触发展开。
- 筛选文案改为 All / Not captured / Captured，避免 New 被理解为新加入的词，Mine 被理解为另一个个人词库。
- Coverage 明确表示“已收录/总词数”，不是掌握率；缩为标题附近的简短信息，不独占大块首屏高度。
- 展开例句保留年份和英语一/二标签。空例句与加载失败分开，移除过时的 2017–2024 范围硬编码。
- 收词后原位反馈已收录；Not captured 下刷新结果，配合可靠性方案中的总数修复与末页回退。

文件：`KaoyanLexiconPage.tsx`、`components/kaoyan/SentenceHighlight.tsx`。分页后端修复复用既有方案，不重复建设。

## 6. 手写编辑：工具稳定、参考区不挤压画布

依据：当前工具栏源码有多组小按钮，笔宽按钮仅 24×24px；词典参考横幅位于画布上方，展开存在挤占下方空间的风险。本节不依据仓库图片，不将源码推导表述为已观察到的真机问题；实施前先查看当前手写编辑态，再确定是否需要侧栏或独立参考面板。

方案：

- 常用工具固定为笔、橡皮、撤销、重做；笔宽仍可直达。纸张、加页、清空放次级工具区，清空与普通工具分隔并有保护。
- 点击热区以 44×44px 为项目设计目标，图标本身可以较小；工具使用图标加短文案，选中状态清晰。窄屏采用稳定的两排分组，不随状态任意换行挤动画布。
- 状态文字简化为当前输入模式；详细诊断保留到管理/诊断页面，不占常用工具区。
- 桌面或平板横屏的词典参考放在画布侧边；手机用可关闭的独立参考面板，避免展开长例句后画布高度大幅变化。阅读参考时停止绘制输入。
- 保存与模式切换位置固定可达，保存期间有状态；退出存在未保存修改时提供保存/放弃/继续编辑的明确选择。
- 本轮仅调整外围布局，不改笔迹采样、滤波、坐标或渲染算法。验证画布容器缩放后坐标映射与已有笔迹比例仍正确。

文件：`CanvasPad.tsx`、`CanvasFullscreen.tsx`、`QuickCapturePage.tsx`、`WordDetailPage.tsx`。

## 7. 单词详情和设置：沿用现有结构，调整优先级

详情页：保留桌面两列；手机顺序为单词/音标 → 主释义或手写卡 → 编辑/补充 → 例句与其他释义。AI Enrich 当前视觉上比编辑更突出，改为辅助操作；Edit primary card、Add meaning 根据是否已有释义形成清楚主次。返回应优先回到来源列表或复习上下文，直接链接打开时有安全回退。进入详情不应无意重开复习会话。

设置页：已有 Profile / Data / LLM / Admin 分组，无需再拆多个新页面。将 LLM 的用户文案改为 AI，技术供应商配置置于可展开区；账户入口承接反馈和退出。已有偏好可集中显示，但新增提醒、学习目标等配置不纳入本轮。管理员运行信息继续只对管理员显示。

文件：`WordDetailPage.tsx`、`SettingsPage.tsx`、`App.tsx`，必要时协调复习会话恢复逻辑。

## 8. 文案、可读性和交互一致性

- 考虑最近提交有意统一英文导航，本轮默认保留英文导航和操作文案；英文单词、中文释义按学习内容保留。考研页系统文案及查词提示采用同一套术语。全站中文化是可选偏好，不默认推翻近期决定。
- 关键状态、正文、错误提示不使用过浅灰色；完成后实际测量对比度。10–11px 文本仅用于非关键辅助信息，不能承担核心操作指示。
- 为搜索框、纯图标按钮补可读名称；Tab 焦点覆盖表单、筛选、词典开关和弹层关闭；评分快捷键在输入框、编辑区或弹层内不误触。
- 保留必要的翻面和状态反馈；用户启用减少动态效果时关闭晃动、悬浮位移、无限骨架移动等装饰效果。
- 页面 loading / empty / error / offline / success 分别表达，不把接口失败描述为没有内容。

## 9. 续查补充：把控件外观与实际行为对应起来

以下为源码确认的控制流或控件结构，交互验收待实施时执行。不是基于旧图片或本轮浏览器实测。

### 9.1 释义/用法切换和保存必须可点击（P1）

依据：`QuickCapturePage.tsx` 的 Mode indicator 中 Definition、Usage 都是没有点击处理的 span；`switchTab` 主要由 `~` 快捷键触发。Usage 分支有三个输入框，没有保存按钮，保存依赖键盘事件。

修改：

- 两个标签改为真正的页内切换按钮，显示选中状态，鼠标、触摸、Tab 和方向键均可操作；不改变当前卡片或清空另一个分栏的草稿。
- Usage 增加与 Save definition 同级的 Save usage 按钮；提示快捷键仅作为补充。
- 中文输入法组合输入期间不拦截 Enter；常规 Tab 顺序与屏幕字段顺序一致，不通过 nextElementSibling 猜测下一输入框。
- 最小有效输入和按钮禁用条件与保存函数一致；无效输入给字段提示。

验收：只用触摸即可完成录词 → 切到 Usage → 填用法 → 保存 → 完成；输入法选词不会提前保存，切换回来内容仍在。

### 9.2 已保存与未保存状态统一（P1）

依据：词典释义保存仅设置 `kaoyanSaved`；`handleDone` 只检查 `savedDefs` 和 `savedUsages`。因此仅保存词典释义时，Done 仍走“Please save at least one definition first”分支。另一方面，已存一条释义后再填写第二条，Done 会直接 resetPanel，不检查当前未保存内容。

修改：

- 用统一的“服务器已有释义数量/可复习状态”判断是否完成，所有保存入口更新同一事实，不能以某个本地数组长度代替。
- 独立记录当前编辑是否修改；Done 遇到未保存修改时提供 Save & finish / Discard changes / Keep editing。仅未修改时直接离开。
- 词典释义、文字、用法、手写保存均有进行中状态并防重复点击；失败保留内容。
- 文案明确区分“单词已收录”“草稿已保留在本机”“释义已保存，可复习”。完成退出不自动删除先前已经创建的单词。

验收：只保存词典释义也能完成；保存第一条后填写第二条再退出不会静默丢弃；保存失败或快速双击不错误显示完成。

### 9.3 返回、取消和草稿清理采用同一规则（P1）

依据：收词 Back 调用 `clearHandwritingDraft` 并重置面板，该函数仅移除 localStorage；控制器优先从 IndexedDB 读取草稿。详情 Cancel/Escape 则调用 `clearDraft` 清理两种存储。当前既存在无修改提醒的放弃路径，也存在清理后 IndexedDB 草稿仍可能保留的语义差异。

修改：

- 建立统一编辑退出处理：无修改直接退出；有修改时提供 Save / Keep draft & leave / Discard。Cancel、Back、Escape、页面内导航使用相同规则。
- Keep draft 保留可恢复数据，并提供已有词卡的 Continue editing 入口；Discard 清理 IndexedDB 和兼容 localStorage；服务器保存成功后才清理已提交草稿。
- 等待进行中的草稿写入完成，再执行删除，防止晚完成的写入重新生成已放弃草稿。
- 数据键带账号、单词及释义标识，配合可靠性方案中的账号边界。旧草稿无法确认归属时隔离，不自动加载到当前账号。
- 浏览器强制关闭不保证能弹出确认；依靠草稿持久化兜底。涉及草稿保留的文案只能在持久化成功后显示。

验收：收词和详情两个入口分别测试返回、Escape、切页、保存失败及重新打开；选择保留能恢复，选择放弃不会恢复旧稿，切账号不会恢复其他用户草稿。

### 9.4 Clear 不应同时撤销所有恢复途径（P1）

依据：`useCanvasPadController.ts` 的 `handleClear` 同时清空笔迹、背景、history、undone 和本地草稿；当前 Clear 按钮直接调用它。因此它不能被现有 Undo 恢复。

最小方案：非空画布点击 Clear 时确认范围，提示清空当前画布所有页面且不能撤销；取消默认保留。空画布禁用 Clear。与 Undo、Redo 保持视觉和空间分隔，不让它看起来像普通笔工具。将 Clear 纳入完整可撤销历史属于后续增强，不在本轮承诺实现。

验收：已有多页笔迹和背景预览时，取消清空完整保留；确认后界面与持久化状态一致；不出现“可撤销”的错误提示。

### 9.5 复习快捷键只在复习操作区生效（P1）

依据：`ReviewPage.tsx` 在 window 监听空格及 1–4，没有检查输入目标或弹层；FeedbackDialog 的 textarea 不会阻止这些按键冒泡。根据当前代码，在反馈输入中按空格会触发翻面，卡片背面时数字可触发评分。

修改：

- 输入框、文本域、contenteditable、组合输入、带修饰键、已处理的事件不触发复习快捷键；弹层打开时暂停页面快捷键。
- 忽略持续按住产生的 repeat，避免一次长按连续评分；提交入口同时检查当前卡片和翻面状态。
- 对话框使用明确的对话框语义，打开后焦点进入、关闭后回到触发按钮；确认键只作用于当前弹层。

验收：在复习背面打开反馈，输入含空格和 1–4 的文字不改变卡片、不发送评分；关闭后快捷键恢复。测试只使用隔离环境，不发送真实反馈。

### 9.6 补全建议列表的常规键盘行为（P2）

依据：收词建议支持上下键移动、Tab 应用，Enter 没有处理当前高亮项，而是继续提交输入文本。建议来自已收录单词，选择后再直接创建还会进入重复词错误路径。

修改：高亮建议存在时 Enter 接受并打开已有词卡的补充释义流程；无高亮项时提交当前输入。Esc 关闭建议；点击与键盘结果一致。使用组合框和列表选项语义，避免只有鼠标按下或特殊 Tab 操作才能正确选择。

验收：输入词前缀 → 下键 → Enter 进入高亮词卡，不创建词前缀；鼠标选择和键盘选择一致；输入法确认不误触。

### 9.7 手写模式与长内容的布局约束（P2，待页面验证）

- `CanvasPad` 普通模式使用接近整屏的高度且最小 28rem，再叠加工具栏、词典和保存区；仅改变工具栏排列不能解决短屏空间。收词手写建议复用详情的 fullHeight 编辑容器，让画布填充剩余空间，而不是继续叠加独立高度公式。
- 当前手指输入切换藏在看似状态文本的按钮里。将输入模式明确显示为 Pen only / Finger enabled，并说明仅手写笔模式下手指用于导航的实际支持行为；不自动开启手指绘制，以免破坏防误触习惯。
- 单词详情 h1 没有长词换行约束；增加合理的 `overflow-wrap`，完整保留文本。复习及收词标题同步检查长词，不能只靠 truncate 隐藏。
- 多释义入口将“正在查看的释义”和“默认复习主释义”分开表达，选中其他释义不自动改变主释义；Set primary 是明确动作。

验收：用长单词、5 条释义、多页手写、展开真题例句等数据验证手机和平板；这些布局风险在实际观察前不提升为已复现视觉缺陷。

## 实施顺序和验证

### 第一批：核心操作可达

先修复 P1 操作缺口：可点击的 Definition/Usage 及保存按钮 → 完成状态与草稿退出规则 → Clear 保护及快捷键作用范围。再统一壳层高度与安全区 → 复习三段布局和查词手势 → 收词可见提交按钮 → 删除入口与确认。与 `reliability-fix-plan.zh-CN.md` 的账号隔离、离线同步修复协同，视觉调整不能掩盖数据尚未同步的事实。

### 第二批：找词与编辑效率

我的词库重排及搜索状态 → 考研词库两行布局和直达收词 → 手写外围工具及参考面板 → 详情和设置操作层级。

### 第三批：一致性收尾

文案、按钮热区、字体颜色、键盘焦点、减少动态效果。抽取实际重复的布局和按钮样式，不先建设大而全的设计系统。

| 375×667、390×844 复习 | 普通字号下评分按钮完整可见、不被导航覆盖；查词滚动不评分 |
